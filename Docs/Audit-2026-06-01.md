# Index Repository Audit - 2026-06-01

## Executive summary

**Baseline overall score: 67 / 100**

Index has a credible engine foundation and a surprisingly broad working product surface: the normal Windows Debug, Release, and Dist solutions build; the engine tests pass; and runtime smoke tests pass in all three configurations. Scene rollback, audio cleanup, shader cleanup, prefab workflows, editor play-mode restore, profiling instrumentation, and the WebGPU runtime path all show deliberate engineering work.

The repository is not release-ready yet. The highest-risk gaps are concentrated rather than systemic:

1. Package installation and removal still have trust-boundary holes.
2. Managed job dependencies do not preserve ordering when a dependency is backed by the native job pool.
3. Texture cleanup is wired into scene teardown but still implemented as a no-op.
4. In-place scene deserialization clears entities and game systems without a lifecycle transaction.
5. Two advertised build variants, `--module-profile=core` and `--no-profiler`, do not build.
6. Two bundled fonts are explicitly marked as unsuitable for shipping.

This audit scored the working tree before the remediation pass recorded below. The tree already contained extensive local changes before the audit, so the report does not assume `master` or a clean checkout. The existing `Docs/Audit-2026-05-31.md` tracker was preserved and used as a prior baseline.

## Remediation pass

## Release gates

### P0. Recursive package removal is not containment-checked

`Index-Engine/src/Packages/GitHubSource.cpp:370-399` accepts `packageId`, removes a project reference, joins `RootDirectory/Packages/packageId`, and calls `std::filesystem::remove_all`. The install path validates `IsSafePathComponent` and canonical containment at `Index-Engine/src/Packages/GitHubSource.cpp:316-345`; the removal path does neither.

If an unsafe identifier reaches `Remove`, the cleanup target can escape the intended package root. Fix this before exposing package removal to untrusted registry or project metadata:

1. Create one shared `ResolveContainedPackagePath` helper.
2. Reject empty, `.`, `..`, separator-containing, rooted, reserved, and canonical-escape identifiers.
3. Require the resolved path to be a descendant of `<project>/Packages`.
4. Test malicious identifiers and ensure no delete occurs outside a temporary package root.

### P0. Registry SHA-256 enforcement is optional

`Index-PackageTool/Program.cs:397` accepts the expected hash, but `Index-PackageTool/Program.cs:466` only compares it when the string is non-empty. The editor treats the cloud-registry `sha256` member as optional at `Index-Editor/src/Gui/PackageManagerPanel.cpp:1500`.

Require exactly 64 hexadecimal characters before download or extraction. Reject missing hashes in registry parsing and surface a clear UI error. Add compressed-size, extracted-size, and file-count limits while touching this path.

### P0. Legacy DLL package downloads are unverified

`Index-Engine/src/Packages/GitHubSource.cpp:308-364` downloads `dllUrl` through `github-download` and adds the DLL reference without checking a checksum or signature.

Require SHA-256 in the legacy index and verify before project mutation. Prefer converging this path on the registry installer's trusted metadata model so there is one download policy.

### P0. Managed job dependencies can execute out of order

`Index-ScriptCore/Source/Index/Jobs/Job.cs:198`, `:217`, `:256`, `:303`, `:344`, and `:387` pass `dependency.InnerTask` into `StartScheduled`. A native-backed `JobHandle` is valid but has a null `InnerTask`, so dependent work can start immediately. `CombineDependencies` at `Index-ScriptCore/Source/Index/Jobs/Job.cs:446-489` also skips native-backed handles, which makes `WaitAll` incomplete for native jobs.

Do not patch this by casually calling `AsTask()`: `AsTask()` waits and releases the native handle, so ownership and repeated waits need an explicit contract. Prefer one of:

1. Add native dependency primitives and keep dependency chains in the native scheduler.
2. Add retained native-handle ownership when materializing a managed task.
3. Centralize dependency conversion and make `Complete`, `AsTask`, `CombineDependencies`, and `WaitAll` obey the same ownership rules.

Add managed regression tests for typed native job -> typed job, typed native job -> `Action`, `CombineDependencies`, `WaitAll`, failure propagation, and repeated completion behavior.

### P0. Bundled fonts are not shippable as documented

`Index-Runtime/IndexAssets/Fonts/LICENSES.md:22-32` explicitly marks `DefaultSans-Regular.ttf` and `Quicksand_Book.otf` as unsuitable for shipping.

Replace them with documented OFL or Apache-licensed builds, update attribution, and verify packaged runtime assets.

## High-priority correctness and performance findings

### P1. Texture purge is wired but implemented as a no-op

`SceneManager` calls `TextureManager::PurgeUnreferenced()` during unload at `Index-Engine/src/Scene/SceneManager.cpp:366` and `:483`. The implementation at `Index-Engine/src/Graphics/TextureManager.cpp:363-366` only returns zero. Audio and shader managers already provide working reference-provider models at `Index-Engine/src/Audio/AudioManager.cpp:403-442` and `Index-Engine/src/Graphics/ShaderManager.cpp:211-237`.

Implement texture reference collection across loaded scenes and registered non-ECS providers, preserve default textures, then unload unreferenced handles. Cover repeated scene switches, splash/preview holders, and stale-generation handles.

### P1. In-place scene deserialization bypasses lifecycle teardown

`SceneSerializer::LoadFromFile` clears entities and game systems directly at `Index-Engine/src/Serialization/SceneSerializerDeserialize.cpp:800-801`. Existing editor and scripting call sites load into already-live scenes, including `Index-Editor/src/Systems/ImGuiEditorLayer.cpp:1496-1501`, `Index-Editor/src/Gui/AssetBrowser.cpp:605`, and `Index-Engine/src/Scripting/ScriptBindings.cpp:731`.

Introduce a scene-content replacement transaction that performs teardown, clear, deserialize, validation, and fresh lifecycle start. Route loaded-scene callers through it. Add a sentinel `ISystem` test proving `OnDestroy`, `Awake`, and `Start` ordering.

### P1. Advertised standalone core profile does not build

`README.md:98-113` documents `--module-profile core`. CI comments in `.github/workflows/ci.yml` acknowledge that validation was removed because optional-module headers still leak into the core build. Local verification failed on GLFW includes from core-profile sources.

Either make the profile a real supported source set and restore CI validation, or remove it from user-facing documentation until it is supported.

### P1. Stripped-profiler build does not link

`Index-Runtime/premake5.lua:21-29` omits `ProfilerPanel.cpp` under `--no-profiler`, while `Index-Runtime/src/RuntimeProfilerLayer.hpp:4` still includes `ProfilerPanel.hpp` and owns a `ProfilerPanel` member. The empty method stubs in `Index-Runtime/src/RuntimeProfilerLayer.cpp:61-68` do not prevent the member destructor from referencing missing symbols.

Compile out the owner member with the profiler flag, or provide a complete stripped implementation. Add a `--no-profiler` CI build.

### P1. Post-processing creates bind groups in per-frame pass execution

Pipelines are cached, but bind groups are created in hot pass paths at `Index-Engine/src/Graphics/PostProcessing/PostProcessor.cpp:547`, `:792`, and `:1027`.

Cache bind groups by pass type, source view, destination generation where needed, sampler, and uniform buffer. Invalidate caches when framebuffer views are recreated or the renderer shuts down. Add a render-loop metric or validation test that detects repeated bind-group allocation after warm-up.

### P1. DLL export boundary is too implementation-heavy

Windows Debug and Dist builds emit a large volume of C4251/C4275 warnings for exported classes containing STL, GLM, chrono, smart-pointer, and other implementation types. Representative surfaces include `Core/Application.hpp`, `Core/Input.hpp`, `Project/IndexProject.hpp`, `Serialization/Json.hpp`, and `Graphics/Text/Font.hpp`.

Define the supported ABI explicitly. Use a narrow C ABI for native packages where possible, move implementation state behind pImpl where ABI stability matters, reduce unnecessary `INDEX_API` class exports, and track a curated warning budget in CI.

## Strengths worth preserving

1. Default Windows Debug, Release, and Dist builds all complete, and all runtime smoke checks pass.
2. The engine suite passes 51 cases and 340 assertions in Debug and Release.
3. `SceneManager` has symmetric rollback cleanup for Box2D and Axiom physics.
4. Audio purge and shader purge provide concrete patterns for finishing texture cleanup.
5. Registry zip extraction normalizes separators and rejects traversal attempts in `Index-PackageTool/Program.cs:473-513`.
6. The editor play-mode restore path now accounts for multiple loaded scenes.
7. The CI workflow covers Windows and Linux release paths, Linux Debug targets, engine tests, and runtime smoke tests.
8. Tracy and the in-editor profiler share instrumentation macros cleanly when profiling is enabled.

## Recommended implementation order

### Before shipping

1. Harden package removal containment, require hashes, verify legacy DLLs, and add archive limits.
2. Replace the two unlicensed or unclear-license fonts and verify packaged assets.
3. Fix managed/native job dependency ordering and handle ownership.
4. Implement texture purge and stress repeated scene load/unload.
5. Add lifecycle-correct scene-content replacement.
6. Repair `--no-profiler` and either repair or temporarily withdraw the core profile.

### Next stabilization sprint

1. Cache post-processing bind groups.
2. Add portable SHA-256 and serialize language downloader transitions.
3. Replace mutable JSON error fallbacks.
4. Harden native script accessors, UI transient state, and hierarchy propagation.
5. Wrap Premake package manifest evaluation and propagate module defines.

### Longer-term architecture

1. Define a deliberately narrow native extension ABI.
2. Add package lockfiles and a single trusted installer path.
3. Convert asset discovery to incremental updates.
4. Expand automated render validation and cross-platform security regression tests.
