# Index Engine — Audit Findings & Tracker (2026-05-31)

Full pre-release audit. 11 parallel subsystem auditors (full source reads) + Opus
verification of the most severe findings against the real code. Severities below are
the **verified** assessment — several auditor-reported "High/Critical" items were
downgraded after I confirmed the code already guards against them (noted inline with ✓).

This file is issue-ready: each unchecked box maps to one GitHub issue. Items already
fixed in the audit pass are checked and tagged `(fixed <date>)`.

**Legend** — Severity: 🔴 Blocker · 🟠 High · 🟡 Medium · ⚪ Low/hygiene.
Confidence: ✓ = verified against code by reviewer · ~ = auditor-reported, not re-verified.

## 1 · Release blockers 🔴

- [x] 🔴 **Editor crash — CONFIRMED & FIXED.** Root cause: `ImGuiEditorLayer.cpp`
  `ForEachComponentInfo` — a prefab **Revert** recreates the entity + calls `SelectEntity`
  mid-iteration; the loop then kept using the stale `entity`/`entitySpan` for later
  components (use-after-destroy on the EnTT registry). Fixed via the
  `selectionInvalidatedByRevert` latch. Candidate (b) (prefab-file-delete) was investigated
  and is **not** a bug (`ClosePrefabEditing` resets before use). The `GetPreviewTexture`
  "wrong-pointer" report was a **false positive** (the pushed entry stays `back()` after a
  non-back `erase`).
- [x] 🔴 **[CONC] `PackageManagerPanel.cpp` git clone + Python scaffolder** — were blocking
  the render thread. **(fixed 2026-05-31: worker threads + main-thread poll continuation)**
- [x] 🔴 **[LOGIC] `ImGuiEditorLayer.cpp` / play-mode restore — FIXED.** Was: `m_PlayModeScenePath`
  is a single `std::string`; only the active scene was saved at entry and reloaded on Stop, so
  with additive scenes (a core feature) all non-active scenes carried their play-mode runtime
  state back into edit mode. **(fixed 2026-05-31: `m_PlayModeScenes` snapshots EVERY loaded
  scene (name+path) at entry — saving each dirty one — and the Stop path reloads all of them
  from disk via `ForeachLoadedScene`; build-validated)** ✓
- [ ] 🔴 **Missing font licenses** (from project notes) — non-code; resolve before ship.

## 2 · High 🟠

- [x] 🟠 **[MEM] `Framebuffer.cpp` `Recreate` — FIXED.** Same-size fast-path ignored a
  `colorFormat` change (RGBA8↔RGBA16F) → kept the old-format texture, mismatching the render
  pass. **(fixed 2026-05-31: added an `m_ColorFormat` member, set on (re)create + transferred
  by the move ops, and folded into the fast-path guard; build-validated)**
- [ ] 🟠 **[PERF/PHILO] `PostProcessor.cpp:665/928/1199`** — `CreateBindGroup` per effect
  **per frame** (~96 driver allocs/frame). Violates "no hidden allocs in hot paths".
  **Design (deferred — needs render-testing):** cache the bind group per pass-type keyed by
  the source `WGPUTextureView`, and clear all caches when the input size changes (the only
  time the FBO views are recreated — `:707/983/1086`). Sound in principle, but a wrong key or
  a missed eviction = a dangling-view Dawn validation error / GPU-resource leak, so it must be
  validated with the editor running rather than compile-only. Left for a focused pass.
- [ ] 🟠 **[LOGIC] `SceneSerializerDeserialize.cpp:818` + `Scene.cpp:1125`** ~ — in-place
  reload calls `ClearEntities()` without `DestroyScene()`; engine systems get no
  `OnDestroy`/re-`Awake`, hold stale managed handles. **Fix:** teardown before clear,
  re-`Awake`/`Start` after, gated on `IsLoaded()`.
- [x] 🟠 **[MEM] IndexPhys scene sweep — FIXED.** Box2D had a `DestroyAllBodiesForScene`
  belt-and-suspenders sweep on scene unload; `IndexPhysicsWorld2D` (Fast* colliders) did not,
  so a thrown-mid-clear `ClearEntities` could leave a dangling `Scene*` in `m_BodyToScene`
  (read every frame by `DispatchScriptContacts`). **(fixed 2026-05-31: added
  `IndexPhysicsWorld2D::PurgeBodiesForScene(Scene*)` — collects the scene's bodies via
  `m_BodyToScene`, then reuses `DestroyAllCollidersOnEntity` + `DestroyBody` per entity; wired
  into `SceneManager::ReleaseScene` beside the Box2D sweep; build-validated)** **[re-audit
  2026-05-31: an independent pass caught a DOUBLE-DETACH regression — the first ordering called
  `m_World.DetachCollider` twice on the same body. FIXED by reordering to `DestroyBody` →
  `DestroyAllCollidersOnEntity` (whose guarded detach then no-ops since the body is gone);
  build-validated. NOTE: `RollbackSceneLoad` still lacks the symmetric purge — tracked below.]**
- [x] 🟠 **[BUILD] `package-loader.lua` `pinvoke_dll` — FIXED (verified against a scaffolded
  bridge package).** Was validated to require a native sibling but otherwise never consumed,
  so a typo'd `pinvoke_dll` only surfaced at runtime (DllNotFound). **(fixed 2026-05-31:
  (1) validation now asserts `pinvoke_dll == "Pkg.<Name>.Native"` and fails loud at premake
  time — confirmed by a negative test that triggered the PackageError; (2) `RegisterCSharpProject`
  now `dependson`s the native sibling so the native DLL build-orders before the C# assembly —
  confirmed as a `ProjectDependencies` entry in the generated `Index.sln`.)**
- [x] ⚪ **[BUILD] `package-loader.lua:282` `private_includes` "leak" — NOT A BUG (false
  positive, verified).** The original finding assumed CMake-style transitive include
  propagation. premake5 does **not** propagate `includedirs` to projects that `links` a
  package, and package-to-package deps here only `links`+`dependson` (`:346-347`) with no
  include forwarding — so `private_includes` and `includes` both feed only the package's OWN
  compile; nothing leaks to dependents. The public/private split is currently inert (a feature
  gap if public headers should ever be visible to dependents), not a leak. No change made.
- [x] 🟠 **[CONC] `Event.hpp` dispatch tracking — FIXED.** A single shared
  `atomic<thread::id>` save/restore corrupted under concurrent `Invoke` (the shared_lock
  permits concurrent dispatch, e.g. `Log::OnLog` from worker threads) → a stale id caused
  spurious `logic_error` from Add/Remove/Clear. **(fixed 2026-05-31: replaced with a
  thread_local per-(thread,instance) depth map + RAII restore; build-validated)**

## Cross-cutting themes (worth a dedicated sweep)

1. **Dangling entity handles across frames / scene-swap / play-toggle** — recurring in
   editor + `UIEventSystem`. A single invariant ("invalidate selection & caches on scene
   swap and play-mode toggle") would close a whole crash class.
2. **Per-frame work in "every frame" paths** — PostProcessor bind groups, AssetBrowser copy,
   PropertyDrawer buffer, override-patch strings, ReferencePicker rebuild. Each small, but
   against the performance-first principle.
3. **Untrusted-input hardening** — BinaryArchive count (fixed), `stoull` (fixed), project path
   fields, empty SHA in PackageTool. Scene/project/registry files are not trusted input.
4. **Abstraction leaks** — `GetMiniaudioEngine()`, raw `b2Body*` across the physics interface,
   unconsumed `pinvoke_dll`: layer boundaries are designed but punctured.
